# Maison catering

## Что это
Премиальный кейтеринг в Сочи: выездное обслуживание мероприятий и доставка сетов и боксов.
Одностраничный сайт показывает уровень работы, даёт порядок цен и приводит к заявке в мессенджер.

## Тип проекта
[ ] Концепт: только hero
[ ] Концепт: лендинг на 3–5 блоков
[x] Клиентский сайт

## Стек
Next.js 16 App Router (статический экспорт), TypeScript, Tailwind v4, GSAP + ScrollTrigger, Lenis.
Three.js — нет: на сайте нет WebGL, все сцены — фотографии, типографика и трансформации.
Отклонений от базового стека нет. Вспомогательное, в браузер не попадает: sharp (скрипт `npm run images`),
Python + fontTools (скрипт `scripts/fonts.py`, нужен только при смене гарнитуры).

Next.js 16 отличается от прежних версий: перед правками конфигурации и API сверяться с документацией
в `node_modules/next/dist/docs/` (об этом же — `AGENTS.md`, его создаёт сам Next.js).

## Дизайн-система проекта
Шрифты (рабочая пара до решения арт-директора; сравнение трёх пар — страница `/fonts`):
- Заголовки: Noto Serif Display — Light 300 для заголовков, ExtraLight 200 для вордмарка первого экрана.
  Свободная (SIL OFL), файлы в `src/fonts`, исходники — google/fonts `ofl/notoserifdisplay`.
- Текст: Jost, вариативный 300–500 (Light — текст, Regular — подписи и кнопки). Свободная (SIL OFL), `ofl/jost`.
- Кириллица проверена по таблице cmap: да — в бинарниках обеих гарнитур есть все 66 русских букв
  (А–я, Ё, ё), «», —, …, ₽. Нет: «№» в Jost и знака «−» (U+2212) в Noto Serif Display — на сайте не используются.
- Файлы шрифтов содержат только латиницу и русскую кириллицу (12,7 + 12,8 + 18,1 КБ).
  Метрики антиквы (ширина слова MAISON, высота прописной) — переменные `--wm-*` в `src/app/globals.css`.

Цвета (других цветов в интерфейсе нет, цвет дают только фотографии):
- `--color-milk` — #FAF7F2 — фон страницы, текст на бордовом экране.
- `--color-bordo` — #5E1F2B — заголовки, кнопки, линии, экран заявки.
- `--color-ink` — #241C1C — основной текст; второстепенный — он же с прозрачностью:
  `--color-ink-2` 78 % (контраст 7,4:1), `--color-ink-3` 62 % (4,6:1 — ниже не опускать).
- Линии: бордо с прозрачностью — `--color-line` 30 %, `--color-line-soft` 14 % (только декоративные).
- На бордовом: `--color-milk-2` 80 % (текст), `--color-milk-line` 32 % (линии), `--color-milk-field` 58 % (границы полей, ≥ 3:1).

Сетка и ритм:
- 12 колонок на десктопе (`.grid-12`), 4 на мобильном; поля `--gutter`: 20px на телефоне, 2,5vw на десктопе.
  Левое поле всегда равно правому (`.wrap`).
- Корневой кегль на десктопе привязан к ширине окна (1920 → 16px, 2560 → 21,3px, не меньше 15px):
  композиция пропорционально масштабируется. На телефоне — 100 % (уважает настройку браузера).
  Всё верстается в rem / vw / clamp(), фиксированные px — только линии в 1px.
- Шаг отступов 8px (0,5rem). Между блоками — `--section` (96px … 200px), внутри — кратно шагу.
- Граница мобильной и десктопной композиции — 64rem (1024px). Мобильная — отдельная композиция.
- Кнопки и карточки прямоугольные. Скругления — только у масок фотографий (арки, круги, овал).

Движение:
- Easing: `expo.out` — появление, `power3.out` — отклик на курсор, `power3.inOut` — смена двух состояний.
  Линейных переходов нет, кроме scrub-анимаций, привязанных к скроллу (`src/lib/gsap.ts`).
- Длительности: строка заголовка 1,2 с со сдвигом 0,09 с; текст и линии 1,0–1,4 с; отклик на курсор 0,6–1,1 с.
- Анимируются только `transform`, `opacity` и `clip-path` масок. Исключение одно: высота раскрытия
  в мобильном аккордеоне форматов (одно действие пользователя, не привязано к скроллу).
- Привязка к скроллу: вращение и уход тарелки, параллакс галереи. Плавная прокрутка — Lenis,
  только там, где есть мышь или трекпад; на тач-устройствах прокрутка нативная.
- Появление блоков — декларативно: `data-reveal="lines|fade|rule|mask"` и `data-reveal-group`
  (описание в `globals.css`, исполнение — `src/components/motion/MotionRoot.tsx`). Заголовки — компонент `Lines`.
- `prefers-reduced-motion`: вращение, параллакс и следование за курсором отключены, Lenis не запускается,
  содержимое видно сразу. Без JavaScript всё содержимое тоже видно.

## Законы проекта
1. Три цвета: молочный, бордо, тёплый чёрный. Никаких других цветов, градиентов-украшений и теней, кроме тени под тарелкой.
2. Кнопки прямоугольные, без скруглений.
3. Весь текст — кириллицей. Латиница только в названии Maison catering и названиях мессенджеров (WhatsApp, MAX).
4. Все тексты, цены, составы, шаги, контакты и ссылки — в одном файле `src/data/site.ts`. В компонентах данных нет.
5. Сайт ничего не отправляет на сервер и ничего не хранит. Заявка — готовый текст, который человек сам отправляет в мессенджере.
6. С любого экрана до заявки — одно действие (на десктопе — кнопка в шапке, на телефоне — закреплённая кнопка внизу).
7. Видимые анимации неприкосновенны: скорость оптимизируем только путями, которые их не меняют.
8. Путь публикации задаётся в одном месте — `site.config.mjs` (`basePath` и `siteOrigin`).
   При переезде на maisoncatering.ru: `basePath = ''`, `siteOrigin = 'https://maisoncatering.ru'`. Больше нигде путь не прописан.
9. Телефон везде кликабельный (`tel:`).
10. Красота, которая мешает понять и заказать, — брак.
11. Ничего не выдумывать за клиента: факты (цены, сроки, условия) — только из данных арт-директора.

## Планка качества
- PageSpeed 90+, включая мобильную версию
- 60 fps на всех анимациях
- prefers-reduced-motion учтён
- Проверено на 1920×1080, 2560×1440, 390×844

## Принятые технические решения
- Скиллы ставятся в сессии (`npx skills add …`, `uipro init --ai claude`) и в репозиторий не коммитятся:
  это ~45 МБ стороннего кита. Список источников — `skills-lock.json`.
- Публикация на GitHub Pages идёт только с `main` (workflow `.github/workflows/deploy.yml`): окружение
  `github-pages` отклоняет выкладку с других веток. Работа ведётся в рабочей ветке и попадает на сайт
  после слияния в `main` — по решению арт-директора.
- Изображения готовит `npm run images` (sharp): результат в `public/images/gen` и манифест `src/data/images.gen.ts`
  закоммичены, на CI скрипт не запускается. Исходники не шире 1200px — крупнее варианты не делаются.
  Границы тарелки (центр 511,5×512,5, радиус 378,5px) определены по кадру и записаны в `scripts/images.mjs`:
  при замене кадра hero-dish их нужно определить заново.
- Тень под тарелкой — два радиальных градиента на неподвижной обёртке (тарелка вращается, тень — нет).
  Большое размытие `box-shadow` давало артефакты на мобильном.
- «Два направления»: ширина половин не анимируется. Окна кадров разложены на максимальную ширину и двигаются
  трансформациями от одной переменной `--p` (единицы `cqw`).
- Связь между блоками — data-атрибуты на ссылках, без общего состояния (`src/lib/bus.ts`):
  `data-menu-format` открывает вкладку меню, `data-request-format` и `data-request-set` заполняют форму.
- GSAP и ScrollTrigger подгружаются после первой отрисовки (`src/lib/gsap.ts`), Lenis — динамически и только
  для мыши/трекпада. Поэтому `gsap` и `ScrollTrigger` можно использовать только внутри `defer()`
  (`src/lib/schedule.ts`) или в обработчиках событий; на уровне модуля и при рендере их ещё нет.
- Появление блоков отслеживает IntersectionObserver, а не ScrollTrigger: меньше работы при загрузке.
  Блоки, оказавшиеся выше экрана (заход по якорю, перезагрузка с середины), показываются сразу.
  Шторка `data-reveal="mask"` лежит на первом вложенном элементе, а не на самом кадре: полностью
  обрезанный элемент наблюдатель считает невидимым и никогда бы его не открыл.
- Если GSAP не загрузился, с `<html>` снимается класс `.js` — всё содержимое видно без анимаций
  (`src/lib/schedule.ts`); скрипт в `<head>` делает то же через 4 секунды, если анимации не готовы.
- Границы композиций в JS заданы в rem, как в CSS (`mq.desktop = '(min-width: 64rem)'`): при увеличенном
  шрифте браузера раскладка и поведение переключаются в одной точке.
- Первый экран: высота — окно, но не меньше высоты всей композиции (`--vh` в `hero.module.css`).
  На низком окне (телефон боком, сильное увеличение) блок становится выше окна, а тарелка не исчезает.
- Типографика русского текста — `typo()` из `src/lib/typo.ts` при выводе: предлоги и союзы привязаны
  к следующему слову, тире — к предыдущему. Данные в `site.ts` остаются с обычными пробелами.
- Подписи для скринридеров (`a11y`, `mobileMenu`) тоже лежат в `src/data/site.ts`.
- Стили встроены в HTML (`experimental.inlineCss`): одностраничнику не нужны отдельные запросы за CSS.
- Переход по якорю: позиция блока считается в `src/lib/scroll.ts` и передаётся в Lenis числом
  (по элементу Lenis сам добавляет `scroll-padding-top`, отступ под шапку удваивался).
- MAX: подтверждённого формата ссылки с готовым текстом не найдено, поэтому текст заявки копируется в буфер,
  открывается профиль (`contacts.maxProfileUrl`) и показывается подсказка.
- Локальный просмотр сборки: `npm run build && npm run serve` (отдаёт `out/` под тем же путём, что на хостинге).
  Временные страницы предпросмотра блоков — `src/app/dev/` (в репозиторий не попадают).

## Открытые вопросы
- Выбор шрифтовой пары — по странице `/fonts` (A стоит, B и C — свободные альтернативы, платные — рекомендации).
- Реальные цены, составы и шаги — после ответа клиента (сейчас примерные, все в `src/data/site.ts`).
- Адрес профиля в MAX — заглушка `https://max.ru/` в `contacts.maxProfileUrl`.
- Фотографии сетов и боксов — поле `photo` в данных, карточка уже умеет показывать фото.
- Исходники фотографий крупнее 1200px: на 2560×1440 кадры «Двух направлений» и тарелка слегка мягкие.
- Домен maisoncatering.ru — после подключения поменять две строки в `site.config.mjs`.

## Чего не делать
- Не подключать шрифты с CDN Google Fonts и не брать гарнитуры с формальной кириллицей
  (Sofia Sans, например, по умолчанию отдаёт болгарские формы букв).
- Не выкладывать сайт после каждого пункта — публикация один раз в конце этапа.
- Не создавать новых репозиториев и не трогать другие.
- Не использовать `gsap` / `ScrollTrigger` на уровне модуля или при рендере — сборка падает
  («Cannot read properties of undefined»), потому что библиотека подгружается позже.
- Не анимировать ширину, высоту и отступы; не добавлять тени, скругления кнопок и новые цвета.
- Не ставить большой `box-shadow` с размытием под тарелку — артефакты на мобильном.
- Не дописывать за клиента факты (сроки, условия доставки, состав услуг) — только то, что есть в данных.
- Не вызывать `lenis.scrollTo(элемент)` напрямую — только через `goToSection` / `scrollToTarget`.
- Не вешать `clip-path` (и другие полностью скрывающие стили) на элемент, за которым следит
  IntersectionObserver: он перестаёт «видеть» элемент. Шторку — на вложенный элемент.
- Не ставить `data-reveal-group` на элемент без собственной высоты как на единственную точку срабатывания
  (в «Двух направлениях» дети расставлены абсолютно) — MotionRoot в этом случае наблюдает за первым ребёнком.
- Не задавать границы раскладки в px в JS: только в rem, как в CSS.
- Не оставлять русские строки в компонентах, включая aria-подписи: всё в `src/data/site.ts`.
